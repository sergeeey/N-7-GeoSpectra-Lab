# Отчёт о работе, 2026-11-05: проекторный IPR, Gate 4C и исправление документов

**Статус:** все изменения не закоммичены. Коммитов и пушей не было. Проверочные скрипты, которые не вошли в репозиторий, лежат во временной папке сессии.

## 1. Что проверяли и с чего начали

Исходным материалом был внешний отчёт «Искатель скрытых ограничений» о ускорении `GeoSpectra` (коммит `40ae3f4`). Отчёт предлагал заменить 110 диагонализаций блоков на одну диагонализацию S¹ и обещал ускорение 33–38× и «CANDIDATE_VALIDATED».

## 2. Что проверено и какой результат

### 2.1 Механизм повторного использования спектра

- `D²` на S³ строго диагонален (внедиагональ = 0 при j_max = 1, 2, 3). Блоков 110 при j_max = 3, каждый размера s1. Блок k равен `d_k·I + P`, собственные векторы общие.
- Одна `eigh(P)` даёт те же IPR и r-stat, что текущий блочный решатель, с расхождением ≤ 1e-14 на четырёх сценариях (ring / wilson_ring, clean / W = 20) при s1 = 32.
- Скорость (только решатель, без построения оператора): текущий решатель ~170–250 мс, путь без оператора ~1–2 мс. Это ~100–200×, а не 33–38× из отчёта, потому что база сравнения другая.
- **Оговорка к отчёту:** блочный решатель уже существовал, был точным и документировал блочную структуру. Новизна заявлена завышенно.

### 2.2 Пиковая память

Измерено через `tracemalloc` (только выделения numpy; RSS процесса выше на накладные расходы Python).

| s1 | Плотный оператор, пик построения | Путь без оператора, пик |
|---|---|---|
| 64 | 2,38 ГБ | 0,0005 ГБ |
| 128 | 9,52 ГБ | 0,0012 ГБ |
| 256 | 38,07 ГБ (построение 54 с, решатель 19 с) | 0,0043 ГБ (0,08 с) |

Пик построения растёт примерно вчетверо при удвоении s1. Комментарий в `block_ipr_solver.py` «s1 = 256 feasible on 32 GB» неверен: пик 38 ГБ.

### 2.3 Расхождение IPR и вырождение

Сравнение путей при s1 = 64, 128, 256 (один сид, ring, alpha = 0, clean):

| s1 | IPR блочный | IPR без оператора | Δ (отн.) | r-stat, оба пути |
|---|---|---|---|---|
| 64 | 0,022549716 | 0,022549716 | 0 | 0,405072 (совпадает) |
| 128 | 0,011415260 | 0,011496804 | 8,2e-5 (0,7 %) | 0,347586 (совпадает) |
| 256 | 0,005497205 | 0,005620785 | 1,2e-4 (2,2 %) | 0,352755 (совпадает) |

- r-stat совпадает во всех размерах (до 1e-14), потому что зависит только от мультисета собственных значений.
- IPR отдельного вектора зависит от базиса внутри вырожденных мультиплетов. Вырожденных пар 31, 63, 127 при s1 = 64, 128, 256. На s1 = 64 IPR совпал, потому что блочные `eigh` дали тот же базис (0 из 110 блоков расходятся), на 128 и 256 — нет.
- **Моя ранняя гипотеза** «расхождение только из-за границы отсечения» оказалась неполной: при s1 = 128 граница не попадает на вырождение, но IPR всё равно расходится, потому что сумма по полностью включённой мультиплете тоже зависит от базиса.

### 2.4 Усреднение IPR по мультиплетам

Инвариантное определение: `IPR_мульт = Σ_x ρ(x)² / d`, где ρ(x) — диагональ проектора на мультиплет, d — его кратность. Для d = 1 совпадает с обычным IPR.

- Инвариантность: std по 10 случайным поворотам внутри мультиплетов ~1e-17 (наивный IPR на тех же поворотах даёт std 3e-4 … 1e-4).
- Совпадение с наивным там, где вырождения нет: `wilson_ring` clean, точно при s1 = 64 и 256.
- Численная связь с Haar-средним: среднее по случайным базисам мультиплета равно `2/(d+1)·Σρ²/d`. Для d = 2 проверено: отношение 0,6665 при теории 0,6667.

### 2.5 Выбор определения для Gate 4B и Gate 4C

- **Gate 4B** заморожен (`GATE4B_SPECIFICITY_VERDICT_v0.1.24`, FINAL). Его не переопределяли: это подгонка под данные.
- Сравнение контрастов W = 20 / W = 0: для ring проекторный и наивный контраст расходятся на 20–27 % при s1 = 128–256; для wilson_ring расхождение < 1 %. Наклоны по логарифмам одинаковые (~1,1 для ring). IPR(W = 20) расходится < 0,5 %.
- Выбрано проекторное определение с явным соглашением (`Σρ²/d`, без 2/(d+1)). Одобрено пользователем, работа продолжена автономно.
