# Источник порога 0,16 (P4 Gate 4C) — проверка

**Дата:** 2026-11-05. **Статус:** аудит источника. Предрегистрация `GATE4C_PROJECTOR_IPR_PREREG_v0.1.26.md` и её пороги не менялись.

## Что проверено

Порог 0,16 в P4 был взят из `docs/CLAIMS_AND_CAVEATS.md` строка 58: «IPR(W=20) < 16% of ring reference». Я проверил, откуда берётся это число и подтверждается ли оно сохранёнными данными.

## Откуда число

1. `reports/SESSION_REPORT_2026-06-03_04.md`, строка 41: «C1 CONFIRMED (контроли A/B/C отклонены, IPR <16% от ring)».
2. `docs/ROADMAP.md`, таблица контролей: строка «B: scrambled_geometry», `IPR(W=20) max 0.052`, «vs ring ref 16%».
3. Значит, 16 % — это **сводное отношение одного контроля (scrambled geometry) к ring**, а не заранее заданный критерий. В `CLAIM_v0.1.22.md` критерий C1 сформулирован через контраст ≥ 7,15× и плато ±20 %, а не через долю 16 %.

## Что показали сырые данные

Агрегация всех `reports/RUNS/**/*.json` с W = 20 (версия метрики `v0.1.22_negative_controls_true_ipr`):

| Контроль | s1 | n | IPR max | IPR min |
|---|---|---|---|---|
| random_hermitian | 16 / 64 / 128 | 3 каждый | 0,0024 / 0,0005 / 0,0002 | то же |
| scrambled_geometry | 16 | 3 | 0,0545 | 0,0391 |
| scrambled_geometry | 64 | 3 | 0,0119 | 0,0079 |
| scrambled_geometry | 128 | 3 | 0,0099 | 0,0069 |
| **broken_wilson_term (scrambled)** | 16 | 6 | **0,7436** | 0,2190 |
| **broken_wilson_term (scrambled)** | 64 | 6 | **0,6878** | 0,2959 |
| **broken_wilson_term (scrambled)** | 128 | 6 | **0,6547** | 0,3291 |

Контроль с перемешанным Wilson в сохранённых данных даёт IPR 0,22–0,74, то есть **выше ring-референса**. Это совпадает с моим Gate 4C (0,546 при s1 = 64).

## Противоречие с документами

- `docs/ROADMAP.md` и `reports/S3_S1_NEGATIVE_CONTROLS_RESULTS_v0.1.22.md` строка 175 утверждают, что broken Wilson даёт IPR ≈ 0,007 (2 %) и что «все контроли < 5 % ring». **Сырые данные этого не подтверждают** для broken_wilson: максимум 0,74.
- Утверждение «все не-геометрические контроли отклонены, IPR < 16 % ring» (`CLAIMS_AND_CAVEATS.md:58`) **неверно для broken_wilson** и не точно для scrambled geometry (16 % только при s1 = 16, при s1 = 64 ≈ 4 %).
- Вывод C1 CONFIRMED (`SESSION_REPORT`, `WORK_REPORT_2026-06-04_FINAL`) опирается на эти сводки и **не выдерживает проверки по сырым данным** для контроля C.

## Что это значит для Gate 4C

1. Порог 0,16 не был критерием гейта, а сводной цифрой из документа. Его использование как P4 было моей ошибкой при составлении предрегистрации: я взял число из сводки, не проверив его против сырых результатов.
2. Провал P4 в Gate 4C — **согласуется с сырыми данными**, а не является артефактом скрипта. Контроль с перемешанным Wilson локализован сильнее ring.
3. Вывод, что плато и контраст не отделяют геометрию от беспорядка, подтверждается сырыми данными v0.1.22, а не только Gate 4C.

## Что не сделано (нужно решение)

- Документы `ROADMAP.md`, `CLAIMS_AND_CAVEATS.md`, `S3_S1_NEGATIVE_CONTROLS_RESULTS_v0.1.22.md`, `SESSION_REPORT_2026-06-03_04.md` содержат неверное утверждение о broken_wilson. Исправлять их без вашего решения не стал: это публичные документы, и правка влияет на опубликованные выводы.
- Не проверено, почему сводная таблица дала 0,007. Возможные причины: другой набор кейсов или другой seed, либо таблица собрана вручную. Для ответа нужно сверить с отчётом, из которого она была скопирована.
- Не менялась предрегистрация Gate 4C; её P4 по-прежнему использует порог 0,16, и вердикт FAIL остаётся в силе по правилам предрегистрации.

## Источник цифры 0,007 (добавлено 2026-11-05)

**Вероятный источник:** таблица «Control C: broken_wilson_scrambled» в `reports/S3_S1_NEGATIVE_CONTROLS_RESULTS_v0.1.22.md` (строки 46–55). Значения: IPR(W = 0) = 0,0068 при s1 = 16; IPR(W = 20) mean = 0,0055 / 0,0016 / 0,0007 при s1 = 16 / 32 / 64. `ROADMAP` указывает «IPR(W=20) max 0.007» — это совпадает с округлённым 0,0068, то есть **с IPR(W = 0)**, а не с IPR(W = 20). Строго максимум IPR(W = 20) в этой таблице — 0,0055 (округляется до 0,006, не до 0,007).

**Статус:** [INFERRED] — цифра совпадает с таблицей по значению и по контексту, но прямого документа о переносе не найдено.

**Что говорит против этой таблицы.** Она несовместима с сырыми результатами того же прогона (`reports/RUNS/broken_wilson_scrambled_v0.1.22/`):
- В таблице N = 3520 при s1 = 16. По формуле N = 110·s1 должно быть 1760; сырой JSON пишет `N: 1760`.
- В сырых JSON для broken_wilson_term при W = 20 `true_ipr_mean` = 0,22–0,74 (6 кейсов на каждый s1). В таблице — 0,0055.
- Таблица датирована до исправления размерности (`SESSION_REPORT_2026-06-03_04`, пункт 8: «заявленное N≤896 неверно»; Gate 4B использовал s3_dimension = 108).

**Вывод.** Цифра 0,007 не отражает сырые данные. Её источник — табличное значение 0,0068 (IPR(W = 0)), возможно перенесённое с ошибкой, и сводка v0.1.22, построенная раньше исправления размерности. Сырые данные контроля C показывают локализацию выше ring-референса, что подтверждает вывод Gate 4C (P4 не выполнен).
